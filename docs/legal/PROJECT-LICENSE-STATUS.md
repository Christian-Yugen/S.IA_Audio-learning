# Status da licença do código da S·IA

## Situação atual

A licença pública do código da S·IA ainda não foi definida formalmente pela UXBRAS®. Por isso, o repositório não deve incluir uma licença permissiva, uma licença copyleft ou uma licença proprietária inventada pelo processo de organização.

Até que a decisão seja tomada e um arquivo `LICENSE` seja adicionado, o código permanece com **licença não especificada** e todos os direitos permanecem reservados ao titular correspondente.

## Decisão necessária

O responsável pelo projeto deverá decidir:

| Decisão | Pergunta |
|---|---|
| Titularidade | Quem será o titular formal do código? |
| Modelo | O código será aberto, source-available, proprietário ou híbrido? |
| Contribuições | Como contribuições externas serão licenciadas? |
| Marca | Como o nome S·IA e UXBRAS® poderá ser utilizado? |
| Modelos | O código e os pesos neurais terão regras diferentes? |
| Distribuição | O ZIP poderá ser redistribuído livremente? |
| Uso comercial | O uso comercial será permitido, limitado ou condicionado? |

## Dependências de terceiros

A licença do projeto não substitui a auditoria das licenças do runtime WebAssembly, do modelo Piper, da fonemização, dos dados de treinamento e de qualquer futura voz feminina.

Veja [Licenças e distribuição de terceiros](THIRD-PARTY-DISTRIBUTION.md).

## Proibição de publicação enganosa

Não utilizar badges, texto de README ou metadados que indiquem “open source”, “Apache”, “MIT”, “uso comercial permitido” ou equivalentes antes da decisão e da documentação da licença correspondente.

## Ação para liberar o repositório

Depois da decisão, adicionar o arquivo de licença na raiz, atualizar o README, revisar os avisos de terceiros, atualizar as notas de release e registrar a decisão no diretório `docs/decisions/`.
